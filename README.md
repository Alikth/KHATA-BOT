# ربات تلگرامی KHATA-GAMES

این پروژه یک ربات مستقل با دیتابیس PostgreSQL جداگانه است. سورس سایت KHATA-GAMES فقط مرجع قوانین است؛ ربات به Cloudflare D1 متصل نمی‌شود و هیچ داده‌ای در سایت تغییر نمی‌دهد.

## راه‌اندازی ویندوز

1. PostgreSQL را نصب و دیتابیس مستقل `khata_bot` را ایجاد کنید.
2. ابزارهای PostgreSQL Client شامل `pg_dump` و `pg_restore` را نصب و در PATH قرار دهید.
3. `scripts\setup_windows.bat` را اجرا کنید.
4. فایل `.env.example` را به `.env` کپی کنید و `BOT_TOKEN`، `BOT_OWNER_ID`، `ADMIN_CHAT_ID` و `DATABASE_URL` را تنظیم کنید.
5. هش کد مدیریت را با `py scripts\create_admin_hash.py` بسازید و در `ADMIN_PASSWORD_HASH` قرار دهید.
6. اگر دیتابیس از قبل داده دارد، ابتدا `scripts\backup.bat` را اجرا کنید و فایل dump و فایل SHA-256 را نگه دارید.
7. مهاجرت‌ها را به‌ترتیب با `py scripts\migrate.py` اجرا کنید. ابزار فقط نسخه‌های جاافتاده را اعمال می‌کند.
8. ربات را با `START-BOT.bat` اجرا کنید.

ربات بدون ثبت `schema_version=3` شروع به polling نمی‌کند. هرگز مهاجرت‌ها را روی دیتابیس سایت یا Cloudflare D1 اجرا نکنید.

## بکاپ و بازیابی

- اجرای `scripts\backup.bat` یک آرشیو PostgreSQL با فرمت custom می‌سازد، با `pg_restore --list` آن را بررسی می‌کند و فایل SHA-256 می‌سازد.
- بازیابی فقط به یک دیتابیس جدا و خالی مجاز است. ابتدا `RESTORE_DATABASE_URL` را در محیط PowerShell به آدرس دیتابیس آزمایشی تنظیم کنید، سپس `scripts\restore.bat path\to\backup.dump` را اجرا کنید.
- اسکریپت بازیابی دیتابیس مبدأ یا دیتابیس دارای جدول را رد می‌کند و قبل از اجرا، عبارت `RESTORE` را درخواست می‌کند.
- بررسی فهرست آرشیو و checksum، جایگزین یک بازیابی آزمایشی واقعی نیست؛ پیش از انتشار عمومی حتماً بازیابی را روی دیتابیس جداگانه انجام دهید.

## ثبت گروه قلعه

ربات را به گروه یا سوپرگروه اضافه کنید. مالک اصلی در همان گروه اجرا کند:

`/registercastle Winterfell | North | Stark`

نام قلعه، منطقه و خاندان باید دقیقاً مطابق فهرست رسمی بازی باشند. سپس مالک اصلی روی پیام بازیکن Reply می‌زند و می‌نویسد:

`set lord`

منابع اولیه مطابق سایت در یک تراکنش ایجاد می‌شوند. هر گروه به یک قلعه و هر قلعه به یک گروه متصل می‌شود.

## مدیریت

`ADMIN_CHAT_ID` را روی شناسه گروه خصوصی مدیریت بگذارید. فقط مالک اصلی می‌تواند در آن گروه `/admin CODE` را اجرا کند. پیام حاوی کد حذف می‌شود؛ پس از ۵ تلاش ناموفق، ورود برای ۱۵ دقیقه قفل خواهد شد. نشست مدیریتی در حافظه است و با راه‌اندازی مجدد ربات از بین می‌رود.

پس از ورود:
- `/pause` و `/resume`: توقف و ادامه ساعت جهان
- `/status`: وضعیت ساعت
- `/adminwars`، `/adminscenarios`، `/admincastles`، `/admintrades`: فهرست‌های مدیریتی
- `/warresolve ID attacker|defender JSON`: ثبت نتیجه و تلفات نبرد
- `/reviewscenario ID نتیجه`: ثبت نتیجه بررسی سناریو

## دستورات گروه قلعه

- `/profile`، `/economy`، `/buildings`، `/army`
- `/upgrade production farm`، `/upgrade camp swordsman`
- `/workshop upgrade`، `/equipment ladder`، `/port upgrade`
- `/trade`، `/tradepack`، `/offers`
- `/march CastleName land 60 army:swordsman=100;equipment:ladder=2`
- `/march CastleName sea 90 army:swordsman=100;fleet:transport=1,warship=1`
- `/arrivals` سپس `/warcommand ID attack|siege|deploy`
- برای دستور deploy، بعد از آن `/arrival ID garrison|alliance|transfer`
- `/scenario ID متن سناریو`، `/cancelmarch ID`
- `/garrisons`، `/marchgarrison`، `/alliances`، `/alliance`، `/transfers`، `/transfer`

سربازگیری مستقیم مطابق منطق فعلی سایت وجود ندارد؛ کمپ‌ها نیرو را در تسویه هفتگی تولید می‌کنند. تجارت رعیت را نمی‌پذیرد. اگر لشکر پس از رسیدن در بازه ۹۰ دقیقه‌ای دستور یا انتخاب نهایی نگیرد، خودکار لغو می‌شود و دارایی‌ها به مبدأ برمی‌گردند.

## وضعیت و محدودیت‌های انتشار

- CI روی PostgreSQL 16 مهاجرت‌های ۱ تا ۳ را اجرا و جدول‌ها و ستون‌های دیتابیس را با مدل‌های ORM مقایسه می‌کند.
- تست‌های واحد برای بدهی غذای سررسیدگذشته، واردکردن ماژول‌ها و ابزارهای پشتیبان وجود دارد.
- نتیجه نبرد دستی و توسط مالک ثبت می‌شود؛ موتور شبیه‌سازی خودکار نبرد پیاده‌سازی نشده است.
- این Build هنوز تضمین برابری کامل با همه قابلیت‌های سایت نیست. اعلان‌های خصوصی، برخی کنترل‌های مستقل جنگ/تجارت، بازبینی کامل همه قوانین محاصره و تست رفتاری چندقلعه‌ای هنوز نیازمند کارند.
- اتصال واقعی به Telegram Bot API، دیتابیس کاربر، بازیابی آزمایشی بکاپ و استقرار ۲۴/۷ روی VPS در محیط ساخت انجام نشده است.

تا تکمیل تست بازیابی و تست رفتاری چندقلعه‌ای، فقط در محیط آزمایشی استفاده کنید. فایل `.env` را هرگز به GitHub commit نکنید.
